# 配置编辑与面板更新

配置编辑与更新检查从内核 `v1.19.32-optimized-12`、面板 `0.3.6` 开始提供。内核 `v1.19.32-optimized-13` 与面板 `0.3.7` 将自动更新交由内核配置和后台调度管理。面板继续使用现有 `clash-dashboard` 源码及 `clash-dashboard-dist` 静态分支，版本不带额外后缀。

## 编辑当前配置文件

设置页点击“编辑配置”，读取当前内核正在使用的普通 UTF-8 YAML 文件。API 沿用控制器原有鉴权：

| 请求 | 含义 |
| --- | --- |
| `GET /configs/file` | 返回 `path`、`content`、`revision`、`max_size` |
| `PUT /configs/file` | JSON 提交 `content` 和读取时的 `revision`，保存后返回新的文件及修订标识 |

**保存文件与应用配置分开。** 保存检查单个 YAML 映射及基础字段类型，不调用运行态配置解析或应用，也不下载 providers。保存后通过原有“重新加载配置”执行完整校验和应用；读取与保存本身不会清 DNS 缓存、重置观测或中断连接。

不接受任意文件路径。当前配置超过 4 MiB、使用 AGE 加密、非 UTF-8、文件不是普通文件或路径中包含符号链接时，编辑器显示相应限制。嵌入模式禁用该接口。草稿和修订标识仅保留在页面内存，关闭或切换控制器即释放；服务端响应包含 `Cache-Control: no-store`，错误不回显 YAML 或凭据。

保存请求使用单操作闸门，忙时返回 `503` 而不积压配置缓冲。文件变化后返回 `409`，面板保留草稿；单次写入采用同目录临时文件、同步与替换，并保留原权限和属主。Linux 额外保留 POSIX 访问 ACL，Windows 保留属主、组及 DACL。无法保留这些访问权限时不替换原文件。

文件身份、路径及内容修订在替换前重新检查。编辑器请求之间具有冲突保护；不共享此操作锁的外部程序仍可能在最后检查与文件替换之间写入，不承诺跨进程的文件事务。完整重载与直接修改磁盘文件仍按原有方式使用。

## 跟随 external-ui-url 更新面板

更新使用内核当前生效的 `external-ui` 目录、`external-ui-name` 和 **`external-ui-url`**，不硬编码某个仓库。自动更新只比较版本号；第三方面板缺少可识别版本时仍能通过明确的手动安装更新。修改这些配置后需要重载使其生效。

`external-ui` 未指定时，手动更新接口沿用原内核的 `<配置主目录>/ui` 默认目标；是否对外提供该目录仍由原有 `external-ui` 配置决定。自动检查不另建更新源或改写这些配置。

| 请求 | 含义 |
| --- | --- |
| `GET /upgrade/ui` | 读取当前面板与已缓存的更新状态，不发起源下载 |
| `GET /upgrade/ui?check=true` | 检查配置的更新源，验证归档并比较面板版本号 |
| `POST /upgrade/ui` | 安装已验证的更新快照；未检查时先检查 |

状态包含 `supported`、`update_available`、`updating`、当前及可用版本/提交、文件摘要和可选的通用错误状态。当前目录与归档根目录的 `build-info.json` 中 `version` 字段提供版本；**远端版本严格高于本地才返回 `update_available: true` 并允许自动安装**。相同或更低版本不自动更新，即使文件内容或提交发生变化。缺失或无法解析版本时返回 `reason: version-unavailable`、`update_available: false`，面板解释原因并提供“手动安装”；不会回退到文件摘要决定自动更新。响应不暴露更新 URL、URL 内的凭据或私密参数。

自动更新状态通过 `auto_update`、`update_interval`（小时）和可选 `next_check`（RFC3339 时间）只读返回。`GET /configs` 同时返回生效的 `external-ui-auto-update` 和 `external-ui-update-interval`；修改这两个字段仍需编辑 YAML 并重载。

版本按 SemVer 比较，支持可选的 `v` 前缀、预发行标识和构建元数据。例如 `0.3.10 > 0.3.9`，`0.3.7 > 0.3.7-rc.1`；`0.3.7+build1` 与 `0.3.7+build2` 优先级相同。要求完整三段数字，不接受 `latest`、日期串或 `v1.2` 等缩写。

检查使用全局并发控制、5 分钟结果缓存，以及更新源支持时的 ETag / Last-Modified 条件请求。收到 `304 Not Modified` 时复用已知的远端版本；收到新的归档时安全解包并读取它的版本。当前仍从配置 URL 的归档读取元信息，不猜测另一个下载地址。文件 SHA-256 用于检查下载与安装快照、保留静态资源的完整性，不决定是否有新版本。

来源不提供 HTTP 缓存校验信息时，每轮检查需要下载归档后才能读取其版本。下载、解包、文件数量和总大小受限；下载完成并校验后才替换，失败保留旧面板。自动安装在取得安装锁及实际归档后再次比较版本，避免检查与安装之间本地已升级或更新源已回退时降级。检查暂存文件有界保存在面板目录旁，内容只有面板静态资源；DNS 数据和配置草稿不进入这些文件。

单个归档最多 64 MiB，展开后最多 256 MiB、10000 个文件及目录节点，单文件最多 32 MiB，路径深度最多 64 层。只保留上一代静态资源以照顾仍打开的页面，额外保留量同样有界；内部暂存、恢复目录及资源记录不会由 `/ui/` 静态服务提供。更新源或目标目录在重载时改变，会取消旧任务，并在最终替换前再次确认仍是当前配置。

### 在 mihomo YAML 中设置自动更新

以下两项与 `geo-auto-update` / `geo-update-interval` 一样放在 YAML 顶层，间隔单位为小时：

```yaml
external-ui: ui
external-ui-url: "https://github.com/chummumm/mihomo-dns-optimized/archive/refs/heads/clash-dashboard-dist.zip"
external-ui-auto-update: true
external-ui-update-interval: 24
```

保留自己正在使用的 `external-ui`、`external-ui-name` 和 `external-ui-url`，添加或修改两个自动更新字段即可。自动更新默认 `false`，间隔默认 `24`，接受 `1` 至 `2562047` 的整数小时；零、负数、非整数和超过计时器范围的值会使配置校验失败。`6` 表示每 6 小时检查，`168` 表示每 7 天检查。

保存后通过原有重载入口应用。启用或启动后，第一次后台检查在一个配置间隔之后进行；已有的空目录首次下载仍立即执行。相同设置的普通重载继承原定时器，不因重载拖延检查；修改间隔从重载时重新计时。关闭自动更新会停止定时器及其尚未完成的自动任务，更新源或目标目录变化也会取消旧源的任务。手动检查与安装不重置自动计时。

调度由内核进程执行，浏览器关闭、页面隐藏或设备离线均不影响内核继续按时检查。多个浏览器不会创建多个自动更新任务。检查或安装失败后保留现有面板，并在后续周期继续尝试；手动更新与后台任务共用并发闸门，不会同时替换目录。

面板不再提供自动更新开关或浏览器定时安装。旧版保存在浏览器中的自动更新偏好不再生效，也不会自动写入 YAML。升级到面板 `0.3.7` 后刷新页面一次，使已打开的旧版脚本停止运行。更新区显示内核的只读状态，手动检查可获取最新状态。

**面板更新不重载配置、不重启内核、不清理 DNS 缓存或观测。** 完成后仅提示手动刷新。配置编辑器打开时不刷新，准备刷新期间新打开编辑器也会取消页面刷新；刷新页面本身会重新建立浏览器内的连接、日志和 DNS 视图，内核数据继续保留。

页面由当前内核 `/ui/` 托管时，手动刷新只注销当前 UI 范围内的 service worker，再加载新文件，兼容更换为没有 `sw.js` 的其他面板。不会删除控制器设置、其他应用的 service worker 或缓存。外部站点托管的面板提供“打开内核面板”，更新操作不会修改外部站点。

本面板的安装与前端细节见 [面板 README](https://github.com/chummumm/mihomo-dns-optimized/blob/clash-dashboard/README.md)。
