# 配置编辑与自动更新

从内核 `mihomo-optimized-v1.0.0`、面板 `0.4.0` 起，面板来源和安装目录固定。面板与内核的自动更新都由 mihomo YAML 控制，设置页面不再提供检查、手动安装、自动更新开关或更新时间输入。面板源码仍在 `clash-dashboard` 分支，静态文件在 `clash-dashboard-dist` 分支。

## 编辑当前配置文件

设置页点击“编辑配置”，读取当前内核正在使用的普通 UTF-8 YAML 文件。API 沿用控制器原有鉴权：

| 请求 | 含义 |
| --- | --- |
| `GET /configs/file` | 返回 `path`、`content`、`revision`、`max_size` |
| `PUT /configs/file` | JSON 提交 `content` 和读取时的 `revision`，保存后返回新的文件及修订标识 |

**保存文件与应用配置分开。** 保存检查单个 YAML 映射及基础字段类型，不调用运行态配置解析或应用，也不下载 providers。保存后通过原有“重新加载配置”执行完整校验和应用；读取与保存本身不会清 DNS 缓存、重置观测或中断连接。

不接受任意文件路径。当前配置超过 4 MiB、使用 AGE 加密、非 UTF-8、文件不是普通文件或路径中包含符号链接时，编辑器显示相应限制。嵌入模式禁用该接口。草稿和修订标识仅保留在页面内存，关闭或切换控制器即释放；服务端响应包含 `Cache-Control: no-store`，错误不回显 YAML 或凭据。

保存请求使用单操作闸门，忙时返回 `503` 而不积压配置缓冲。文件变化后返回 `409`，面板保留草稿；单次写入采用同目录临时文件、同步与替换，并保留原权限和属主。Linux 额外保留 POSIX 访问 ACL，Windows 保留属主、组及 DACL。无法保留这些访问权限时不替换原文件。

文件身份、路径及内容修订在替换前重新检查。编辑器请求之间具有冲突保护；不共享此操作锁的外部程序仍可能在最后检查与文件替换之间写入，不承诺跨进程的文件事务。完整重载与直接修改磁盘文件仍按原有方式使用。

## 在 YAML 中配置面板和内核自动更新

以下四项与 GEO 自动更新配置一样放在 YAML 顶层，间隔单位为小时：

```yaml
external-ui-auto-update: true
external-ui-update-interval: 24
core-auto-update: true
core-update-interval: 24
```

两组开关均默认 `false`，间隔均默认 `24`。间隔接受 `1` 至 `2562047` 的整数小时；零、负数、非整数或超过计时器范围都会导致配置校验失败。`6` 表示每 6 小时检查，`168` 表示每 7 天检查。可以只启用面板更新或只启用内核更新。

保存 YAML 后通过原有“重新加载配置”应用。`GET /configs` 只读返回这四个生效字段；设置页面不另存浏览器更新策略。旧版浏览器里保存的自动更新偏好也不会转换为 YAML。

启动或启用后，第一次周期检查在一个完整的配置间隔后进行。相同策略重载保留原计时器，不因频繁重载推迟检查；修改间隔会取消旧自动任务并从重载时按新周期计时。关闭开关取消定时器及尚未提交的后台请求。每种更新最多运行一个任务，手动兼容接口与自动更新共用各自的并发闸门。

调度由内核进程执行，浏览器关闭或面板页面不在前台都不影响检查。网络不可用、下载失败或校验失败时保留现有文件，下一周期继续尝试。下载不阻塞配置重载；最终文件替换与策略变更串行提交，已经过时的任务不能迟到安装。

## 固定面板来源与目录

面板固定从下列仓库静态分支归档获取：

`https://github.com/chummumm/mihomo-optimized/archive/refs/heads/clash-dashboard-dist.zip`

文件安装到 mihomo 配置主目录下的 `ui`，并由控制器 `/ui/` 提供静态服务。使用 `-d /path/to/home` 时目录就是 `/path/to/home/ui`；目录不会由配置文件自身所在的位置或当前工作目录另行推断。旧的路径、URL 和子目录配置只为兼容已有 YAML 而接受，均不影响下载或服务目录，也不再作为可配置入口输出。

如果该目录缺失或为空，内核会在后台立即下载初始面板；这属于首次安装，即使周期自动更新关闭也会执行。已有文件时不会通过首次安装覆盖。初始下载与后续检查共用安装闸门，不会因启动和重载重复安装。

### 根据版本号判断面板更新

本地目录和远端归档根目录的 `build-info.json` 中 `version` 字段提供版本。**只有远端版本严格高于本地才允许自动安装。** 相同版本即使文件、摘要或提交号改变，也不会自动覆盖；更低版本不会自动降级。缺失或无法解析版本时不自动安装，且不会改用摘要差异代替版本判断。旧面板的 `name` 和新面板的 `mihomo-optimized` 名称均可读取，不影响版本迁移。

版本按 SemVer 比较，支持可选的 `v` 前缀、预发行标识及构建元数据。例如 `0.4.10 > 0.4.9`，`0.4.0 > 0.4.0-rc.1`；`0.4.0+build1` 与 `0.4.0+build2` 优先级相同。要求完整三段数字。

每次检查读取固定来源归档中的版本信息。使用 5 分钟结果缓存，并在服务器支持时发送 ETag / Last-Modified 条件请求；`304 Not Modified` 可复用已知的远端版本。服务器不提供缓存校验信息时，需要下载归档后才能读取版本。SHA-256 用于验证下载、安装快照和上一代静态资源的完整性，不作为更新条件。

归档最多 64 MiB，展开后最多 256 MiB、10000 个文件及目录节点，单文件最多 32 MiB，路径深度最多 64 层。先下载、安全解包并校验，再原子替换目录；安装前再次检查本地版本和当前策略。失败保留旧面板。只保留上一代有界静态资源，供仍打开的旧页面继续加载；内部暂存、恢复目录和资源记录不由 `/ui/` 提供。

**面板更新不重启内核、不重载配置，也不清理 DNS 缓存或观测。** 已打开页面可在方便时正常刷新获取新文件；更新不会自动刷新并丢弃配置编辑草稿。

以下接口保留给已有集成使用，面板不提供相应更新控件：

| 请求 | 含义 |
| --- | --- |
| `GET /upgrade/ui` | 读取当前版本及已缓存状态，不发起下载 |
| `GET /upgrade/ui?check=true` | 检查固定面板源的归档和版本 |
| `POST /upgrade/ui` | 显式安装固定来源面板，供兼容集成使用 |

状态包含版本、提交、文件摘要、`update_available`、`updating`、只读 `auto_update`、`update_interval` 及可选 `next_check`（RFC3339）。版本不可识别时返回 `reason: version-unavailable` 和 `update_available: false`。接口不提供修改来源或目录的能力。

## 内核自动升级与重启

内核检查固定仓库 [mihomo-optimized 的 Releases](https://github.com/chummumm/mihomo-optimized/releases)。先读取 Latest 的 `version.txt`；确认是可识别且严格高于当前版本的发行版后，后续校验清单和安装包请求都锁定该版本的具体 tag，避免 Latest 在下载途中变化导致混用文件。

新发行版使用 `mihomo-optimized-v<主版本>.<次版本>.<修订版本>`，例如 `mihomo-optimized-v1.0.0`。新命名系列整体高于旧的 `v1.19.x-optimized-N` 系列；新系列内部按三段数字比较。运行中版本不可识别时不自动安装。相同或更低版本也不自动安装，即使强制覆盖的手动兼容接口仍存在。

安装按当前操作系统、CPU 架构及 ABI 选择确切资产名，例如 `mihomo-optimized-v1.0.0-linux-amd64.gz`。先验证发布清单 `SHA256SUMS`，再解包到当前可执行文件旁的临时目录；下载、元信息和解压大小均有上限，取消请求会停止下载和解包。macOS 会对暂存可执行文件执行现有的本地签名步骤。

提交前再次检查更新策略、版本、当前可执行文件身份及 SHA-256。下载期间如有外部程序修改或替换可执行文件，会放弃本次安装，避免覆盖另一次升级。已安装待重启的版本也会记录，防止运行中的旧版本号引起重复安装。旧文件备份到相邻的 `meta-backup` 后才替换。

成功安装会使用内核已有的重启机制，重启时关闭旧 DNS 查询连接和监听器，再启动新版本。内核重启会中断现有代理及控制器连接；启用自动更新表示允许在检查到新版并完成校验后执行这次重启。最终安装和重启与 YAML 重载使用同一个配置事务，关闭或改期的过时任务不会在重载完成后迟到替换或重启。嵌入模式不启用内核自动替换宿主进程。

`.deb`、`.rpm`、`.pkg.tar.zst` 的下载文件名不带发行版本，便于首次部署后由内核自己更新；包内仍有系统包管理器需要的版本元数据。内核自更新只替换可执行文件，**不会修改 dpkg/rpm 等包数据库中记录的安装版本**。实际运行版本以控制器 `/version` 或内核版本报告为准。

旧 `v1.19.32-optimized-13` 内核无法识别新的 tag 格式，需要首次手动迁移到 `mihomo-optimized-v1.0.0`；迁移完成后才能按上述 YAML 策略继续自动更新。

面板源码及安装说明见 [面板 README](https://github.com/chummumm/mihomo-optimized/blob/clash-dashboard/README.md)。
