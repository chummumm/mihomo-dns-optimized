# DNS 状态展示与内存边界

本功能为本仓库的 Clash Dashboard 增加 DNS 概览、查询记录和上游统计。继续使用现有原版面板分支，不替换成另一套面板。数据来自内置 DNS 服务的结构化观测，不从文本日志或连接快照猜测 DNS 请求。

## 开启与生命周期

```yaml
dns:
  enable: true
  observability: true
```

`observability` 默认是 `true`，仅在 DNS 启用时收集。设为 `false` 并完整重载可关闭；无需改动 `enhanced-mode`、上游、分流、测速和嗅探配置。

| 操作 | 查询记录、趋势和上游统计 |
| --- | --- |
| 关闭面板、切到其他页面 | 内核继续在有界内存中收集；面板停止该页请求 |
| 普通完整 reload，DNS 和观测保持开启 | 保留已有数据和实例身份 |
| 关闭 DNS 或设置 `observability: false` 后 reload | 停止收集，释放记录和聚合数据 |
| 重新开启 | 新的实例身份，从零统计 |
| 重启内核 | 从零统计，不恢复历史 |

旧实例的在途请求即使稍后结束，也不能回填到关闭后或重新开启的新实例。观测数据不写文件、不写数据库、不接入浏览器 `localStorage` / `IndexedDB`，API 回复带 `Cache-Control: no-store`。原内核其他功能自己的持久化设置独立生效，本功能不会把 DNS 观测接入这些存储。

## 面板显示什么

### 概览

展示最近 24 小时查询量、正式答案缓存命中、失败、平均处理时间、估算 P95 和按分钟排列的趋势。QPS 使用最近一个完整分钟的请求量除以 60，不把瞬时刷新间隔当成统计窗口。

缓存命中率是同一统计窗口内的 `(新鲜缓存命中 + 过期缓存命中) / 已完成客户端 DNS 查询总数`，分开显示两类命中数，并另给进程累计比例。hosts、Fake IP 和测速候选缓存不计入正式答案缓存命中；窗口内没有查询时显示“—”，不制造 0% 或 100% 的命中率。

缓存命中和回答是否失败是两个独立维度。例如从正式缓存返回 SERVFAIL，会同时增加缓存命中数和错误数，但查询总数只增加一次；明细标为错误，缓存字段仍标明新鲜或过期命中。因而这些分类列不应直接相加来推导查询总数。

进程累计统计与最近 24 小时统计独立于查询明细，明细被淘汰后不会把总数减掉。最近 24 小时采用固定的 1440 个分钟桶，窗口按分钟边界移动。P95 使用固定大小的对数直方图，是分桶上界估算，不是对所有原始耗时排序得到的精确分位数。

热门域名与客户端按**当前保留的查询明细**统计。面板明确标注这一范围，不能把它解释为完整 24 小时或进程全历史排名。

### 查询记录

每条记录包含请求完成时间、原始查询名、客户端、类型、入口协议、处理结果、DNS 返回码、耗时和有限的答案摘要。支持精确域名、客户端、类型和结果过滤，以及按游标翻页。域名过滤不区分大小写，末尾的根点不影响匹配。

查询名在 hosts 别名改写前取得。摘要不会保存整个 DNS 报文、连接对象或路由快照；最多 8 条答案，每条值最多 256 字节。超过时显示截断标记，实际发给客户端的 DNS 答案保持完整。无法可靠确定的选中上游留空，不用配置中的第一个上游冒充。

每页 50 或 100 条，浏览器只保留当前页。暂停后可查看固定页面；记录在服务器被淘汰后不会从磁盘补回。内核重新开启观测或重启时，面板检测实例身份变化并重置游标，避免混用新旧历史。

| 结果 | 含义 |
| --- | --- |
| 新鲜缓存 / 过期缓存 | 正式 DNS 答案缓存命中；过期返回可能另触发后台更新 |
| Hosts / Fake IP | 由相应本地处理器生成回答 |
| 上游 | 未由上述本地回答路径完成，进入解析器上游处理 |
| 拒绝 / 丢弃 | 对应 REJECT / REJECT-DROP 等明确处理 |
| 错误 | 解析错误或失败回答，保留有限的错误分类 |
| 本地 / 未知 | 没有可靠信息归入其他结果时如实展示 |

NXDOMAIN 代表域名不存在，本身不是网络故障。`redir-host-filter` 仅排除反查映射，不是 DNS 拒绝名单，也不应在这里被算作拒绝。

FakeIP 与 DNS 分流同时开启时，本地合成的虚拟地址仍记为 Fake IP，不计为真实答案缓存命中、上游交换或 DNS 连接。FakeIP 模式本地返回的空 AAAA / HTTPS / SVCB 答案记为本地；`fake-ip-filter` 放行到真实解析的查询按实际缓存、上游或拒绝结果记录。后续业务连接触发的内部真实解析不重复算作客户端 DNS 请求。

`rcode://` 等本地合成回答保留本地来源，不计入实际网络交换；本地 REFUSED 显示拒绝，SERVFAIL 等失败返回码显示错误。筛选“错误”也能找到缓存返回的失败回答。

### 上游

每行按实际解析器端点与已确定的实际出站统计交换尝试、成功、错误、取消、超时、失败返回码和耗时。不同规则最终落到同一实际出站时可以归到同一行；同一个解析器经由不同实际出站访问时分别统计。无法可靠确定出站的基础解析或显式动态传输显示为未归属，不猜测为 DIRECT。身份与显示地址分离：用户名、密码、查询参数、片段以及可能含令牌的自定义 DoH 路径不在 API 中展示；不同的隐藏身份仍各自统计。

这里的单位是一次解析器 `Exchange`，不是数据包，也不是客户端请求。一次交换里的协议重连、TCP 回退等内部动作不会被伪装成多个客户端 DNS 请求。缓存命中和候选缓存复用不增加实际上游交换次数；后台刷新、基础解析或一个请求并发访问多个上游，可能增加交换数而不增加外部客户端查询数。

竞争中失去需要而取消的请求单独记为取消，不归入连接错误。因本次取消而关闭本地 socket 或 QUIC stream 的 I/O 错误也归为取消；真实远端故障不能仅因 context 随后取消而被覆盖。期限到达及传输层超时归入超时，同时属于错误。NXDOMAIN 等正常 DNS 答复归入成功；SERVFAIL 等失败返回码另有计数。

面板主要显示成功交换的平均耗时，错误与取消各自保留平均耗时。成功数为零时显示“—”。兼容旧内核时，原混合口径明确显示为“综合平均耗时”，不会把它改名为成功耗时。每种平均值仅使用对应已完成交换，因此在途交换会使“尝试数”暂时大于各完成结果之和。

| API 字段 | 含义 |
| --- | --- |
| `outbound` / `outbound_type` | 已确定的最终出站名称，以及 `direct`、`proxy` 或 `unknown` 分类 |
| `success_elapsed_ms_avg` | 成功交换的平均耗时 |
| `error_elapsed_ms_avg` | 错误交换的平均耗时，包括超时和失败返回码 |
| `canceled_elapsed_ms_avg` | 被取消交换在结束前已经花费的平均时间 |
| `elapsed_ms_avg` | 为兼容保留的综合平均耗时，包含成功、错误和取消 |

这些耗时从实际解析器交换开始计算，可能包含该交换中的基础解析、拨号、TLS / QUIC 建连和协议内重试；不包含收到 DNS 回答后的目标 IP 测速等待。客户端在查询记录中看到的处理时间还包括缓存检查、策略处理与响应模式需要的等待，两种指标不能直接等同。

## 为什么数量不会互相混淆

| 指标 | 统计入口 | 适用范围 |
| --- | --- | --- |
| DNS 查询数 | 内置 DNS 服务完成一个客户端请求 | 包括本地回答和拒绝；不把内部 bootstrap、预取、双栈辅助查询重复算成客户端请求 |
| 实际上游交换数 | 上游客户端执行一次交换 | 可能多于或少于客户端查询数；共享工作只按实际执行计一次 |
| 面板“全部”连接数 | 当前保留的连接集合 | 与各 IP 数字来自同一集合；不代表内核启动以来累计连接数 |

“保留关闭连接”开启时，全部和各 IP 都包含当前保留的已关闭记录。活跃连接不因历史上限而删除；关闭记录最多 5000 条，按关闭保留顺序淘汰。搜索和设备筛选控制显示行，不能悄悄改变设备总量口径；已消失的设备筛选会恢复为全部。

## 有界算法与内存

| 对象 | 边界和处理方式 |
| --- | --- |
| 查询明细 | 最多 4096 条、最长 24 小时，同时受 8 MiB 记账预算约束 |
| 查询答案 | 每条最多 8 个摘要，每个值最多 256 字节 |
| 索引 | 与保留明细一起新增和淘汰；域名和客户端索引用于缩小查询范围 |
| 时间趋势 | 1440 个固定分钟桶；不按运行天数增长 |
| 耗时分位 | 固定大小直方图，不保存无限原始耗时 |
| 上游身份 | 最多 128 个独立身份，再加一行溢出合计 |
| 热门排名 | 用已维护的计数和大小为 10 的堆生成，不对全部历史逐条重算 |
| 浏览器 DNS 数据 | 当前页和当前展示的有界聚合，离页取消请求并释放 |
| 连接列表 | 活跃 Map + 最多 5000 条关闭历史；只渲染视区及少量缓冲行 |

环形保留与顺序淘汰使单条写入的常规成本与已有历史条数无关；一次集中到期的清理为摊销成本。查询读取至多扫描有界候选集合，带精确域名或客户端时优先从较小索引开始。上游聚合也有固定键数上限。

API 的 `accounted_bytes` 是记录、索引和固定结构的保守记账，`memory_limit_bytes` 是这个记账预算。它不是整个 Go 进程 RSS 的硬上限：运行时分配器、垃圾回收、临时 API 序列化以及 DNS 解析器本身的缓存另有内存。页面采用“记账预算”文案，避免把两者混同。

## 控制器 API

四个只读入口位于已有控制器鉴权范围内，使用原有 `secret`：

| 路径 | 内容 |
| --- | --- |
| `GET /dns/observability` | API 版本、开关、实例、容量、保留范围和记账预算 |
| `GET /dns/observability/stats` | 累计、最近 24 小时、分钟趋势和保留记录 Top 10 |
| `GET /dns/observability/queries` | 查询明细，参数为 `limit`、`cursor`、`anchor`、`qname`、`client`、`outcome`、`qtype` |
| `GET /dns/observability/upstreams` | 有界的实际上游交换统计 |

`cursor` 和记录 `id` 使用十进制字符串，避免浏览器整数精度问题。游标是排他的历史边界：新记录到达不会把下一页重复推移。查询窗口仍在后台淘汰，翻到过期范围会如实为空。

从内核 `1.0.4` 起，每次查询还在同一读锁内返回 `total`、`anchor_id` 和 `page_cursors`。`total` 是当前筛选、历史上界以内仍保留的匹配数，不是全局 `retained`；`anchor_id` 是包含在范围内的查询 ID 上界。`page_cursors` 首项为空字符串，其余项为各页排他游标。首页请求 `?limit=50`（可附筛选）；第 N 页请求同时传 `anchor=<anchor_id>` 和 `cursor=<page_cursors[N-1]>`。字段使用十进制字符串表示 ID，保留 uint64 精度。零匹配返回 `total: 0` 和 `page_cursors: [""]`。

实时首页刷新不带 `anchor`，历史页始终带上界，不把新到记录混入旧页。TTL 或容量淘汰会减少匹配总数；面板发现当前页超出真实末页时自动跳回末页。前端无需扫描完整日志来计数，只保留当前页及最多约 82 个页边界（4096 条、每页 50 条）。旧接口缺少分页元数据时，仍可首页、上一页和下一页，精确总数与直接跳页明确显示不可用。

新版面板连接不支持此 API 的旧内核时，显示“不支持 DNS 观测”，停止重复轮询；普通连接、节点等页面继续使用原接口。API 不发起主动 DNS 查询，原有 `/dns/query` 的行为独立保留。

## 更新和验证

内核使用本仓库正式 Releases，面板来源固定为 `clash-dashboard-dist`，目录固定为 HomeDir 下的 `ui`。两者分别由 YAML 顶层的 `core-auto-update` / `core-update-interval` 和 `external-ui-auto-update` / `external-ui-update-interval` 控制。面板 `0.4.6` 提供统一“检查并更新”入口，由内核处理已配置的规则集、GeoData、面板和内核；自动更新策略仍只放在 YAML。后台面板更新不清空 DNS 数据，内核升级成功后自动重启并重建内存状态。完整说明见[面板及内核维护说明](dashboard-management.md)。

```bash
bash scripts/ci-check.sh test
go build -tags with_gvisor -o dns-route-kernel
python3 scripts/test-dns-observability.py ./dns-route-kernel
```

最后一项使用本机模拟 UDP 上游和临时控制器，验证鉴权、无缓存响应、真实 DNS 回答、缓存与上游计数、hosts 别名、NXDOMAIN、拒绝/丢弃、UDP/TCP、答案截断、索引与翻页、普通 reload、记录淘汰、关闭/重新开启和进程重启，并检查查询观测没有修改运行目录文件。Linux amd64 正式构建执行同一实际二进制验收；其他平台的构建成功不等于已经在相应设备运行过。
